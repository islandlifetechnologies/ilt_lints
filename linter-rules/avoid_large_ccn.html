avoid_large_ccn

Stable No quick fix #experimental #quality

Avoid deeply nested control flow and excessive branching in a single function; extract smaller, single-purpose helper functions or use early returns and polymorphism to keep cyclomatic complexity low.

Details

AVOID deeply nested control flow and excessive branching in a single function; extract smaller, single-purpose helper functions or use early returns and polymorphism to keep cyclomatic complexity low.

Calculates the cyclomatic complexity number (CCN) for every function, method, and constructor and triggers when the complexity exceeds the configured ccn threshold (defaults to 20). Each conditional branch, loop, case, catch, ternary operator (?:), null-coalescing operator (??, ??=), and logical operator (&&, ||) increases the function's cyclomatic complexity.

Examples

BAD: 
// High cyclomatic complexity caused by many chained branches in a single function.
String classifyScore(int score, {required bool bonus, required bool penalty}) {
  if (score > 90 && bonus) {
    return 'S';
  } else if (score > 80 || (score > 75 && bonus)) {
    return penalty ? 'B+' : 'A';
  } else if (score > 70 && !penalty) {
    return 'B';
  } else if (score > 60 || bonus) {
    return penalty ? 'C-' : 'C';
  }
  return 'F';
}
GOOD: 
// Complexity is reduced by extracting focused helper functions and simplifying branches.
String classifyScore(int score, {required bool bonus, required bool penalty}) {
  final adjusted = score + (bonus ? 5 : 0) - (penalty ? 5 : 0);
  return _gradeForAdjustedScore(adjusted);
}

String _gradeForAdjustedScore(int score) => switch (score) {
  > 90 => 'S',
  > 80 => 'A',
  > 70 => 'B',
  > 60 => 'C',
  _ => 'F',
};

How to enable

To enable the avoid_large_ccn rule, add it to your analysis_options.yaml file:

analysis_options.yaml 
plugins:
  ilt_lints:
    version: ^2.0.0
    diagnostics:
      avoid_large_ccn: true

# Optional configuration (shown with default):
avoid_large_ccn:
  ccn: 20
